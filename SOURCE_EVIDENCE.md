# Data-source evidence and limits

This file records external evidence used for the current core slice. All community-facing endpoints below are undocumented or non-contractual; none is a provider SLA or stable contract. The app must preserve local-only, foreground-only behavior and expose failures rather than infer missing data.

## Quote and minute-history sources

- [efinance current getter implementation](https://raw.githubusercontent.com/Micro-sheep/efinance/main/efinance/common/getter.py) uses Eastmoney `https://push2his.eastmoney.com/api/qt/stock/kline/get`, requests `fields1=f1,...,f13`, `fields2=f51,...,f63`, and documents `klt=1` as one-minute history. This supports using a public 1-minute history route, but does not guarantee retention or response stability.
- [efinance v0.3.3 source documentation](https://efinance.readthedocs.io/en/v0.3.3/_modules/efinance/stock/getter/) describes the `klt=1` minute option and the same K-line endpoint/field scheme.
- [Community Tencent quote field walkthrough](https://www.cnblogs.com/soarowl/p/20523904) documents the text/GBK `qt.gtimg.cn` response and core positions: latest/previous close/open at indexes 3/4/5, timestamp index 30, high/low 33/34, volume index 36, amount in 10,000-yuan units at index 37. This is community evidence, not a Tencent contract.

## Read-only quote probes

On 2026-11-14 (Asia/Shanghai), one GET to Eastmoney `https://push2.eastmoney.com/api/qt/ulist.np/get` for four symbols returned HTTP 200 JSON with `data.diff`, keys including `f2/f3/f4/f5/f6/f12/f14/f15/f16/f17/f18/f60/f86/f124`. `f124` was a plausible Unix provider timestamp. Three core indices were present alongside a stock.

One GET to Eastmoney `https://push2his.eastmoney.com/api/qt/stock/trends2/get` for `secid=1.600000`, `ndays=5`, returned 1,205 trend rows spanning 2026-11-09 through 2026-11-13. Comparing a row from that response with Eastmoney's separate `kline/get?klt=1` minute-K-line response suggests the trends row begins `time,open,close,high,low,volume,amount,...` (`f51` through `f57`); this field interpretation is observed/inferred only and must be contract-tested against live changes. The same-date `kline/get?klt=1` probe returned 240 rows from 09:31 to 15:00, illustrating that the exact time window and session endpoint can differ by route.

One GET to `https://qt.gtimg.cn/q=sh600000,sh000001,sz399001,sz399006` returned HTTP 200 GBK text. It included stock and core index symbols, with provider timestamps embedded in the text response. The fetched response was consistent with the community field walkthrough.

## Deliberate safety limits

- Eastmoney `trends2` is queried by one `secid` at a time. The adapter caps one reopen reconciliation at 50 symbols and uses a `push2his.eastmoney.com` budget of at most 4 requests/second and 50 requests per foreground session. History reconciliation runs alongside the first foreground quote fetch. Fifty serial requests may take about 12.5 seconds; skipped symbols and truncated coverage are reported. It stores/evaluates returned minute bars only, not every trade or every intraminute event. The observed `ndays=5` window is not treated as a guaranteed five-session recovery period.
- The unauthenticated quote endpoints do not provide a verified, complete per-stock daily `up_limit` and `down_limit` pair in the fields used here. A limit-up/down pool is not the same as an authoritative pair for every watched security; the captured 2026-11-13 response contains `data:null`, so pool counts and seal amounts remain unknown. Tushare `stk_limit` requires user credentials/entitlement and none is configured. Current 2026 exchange rules establish the standard percentages and tick math, but `LocalDailyLimitSource` is only a local formula estimate, not an exchange quote. Code-prefix board recognition and ST-name matching are heuristics; the runtime has no authoritative listing-date or delisting-state provider. IPO/delisting exceptions stay unavailable when explicitly indicated, but a missing IPO session index is disclosed as a non-IPO assumption. `seal_break` inherits that uncertainty and only counts transitions observed while the app is foregrounded.
- Public feeds can throttle, change field meanings, omit timestamps, or return delayed/last-close data. Each stored quote carries source ID, retrieval time and a flag indicating whether its timestamp came from the provider; UI freshness uses provider timestamp when available and says `unknown` otherwise.
- The news and public-list endpoints above have no verified contractual rate, freshness, completeness, or availability promises. They are only attempted from user-triggered/foreground code, use local deduplication, and must report an explicit blocked/error status on HTTP failures or schema drift.

## Official 2026 daily price-limit rules

- The [Shanghai Stock Exchange Trading Rules (2026 revision), Article 3.3.13](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20260424_10816492.shtml) state a 10% general limit, no limit for the first five trading days after an IPO, and no limit on the first day of delisting-period trading or relisting. Article 3.3.11 specifies a CNY 0.01 A-share tick; Article 3.3.17 specifies rounding and at-least-one-tick handling.
- The [CSRC Shanghai branch's 2026-07-06 implementation summary](https://www.csrc.gov.cn/shanghai/c105566/c7643909/content.shtml) reports that main-board risk-warning (ST/*ST) limits became 10% from 2026-07-06; ChiNext and STAR risk-warning limits remain 20%, while BSE risk-warning limits remain 30%. The [SSE's 2026 rules-in-effect release](https://english.sse.com.cn/news/newsrelease/voice/c/c_20260708_10824778.shtml) independently confirms main-board ST limits rose from 5% to 10% under the revised rules.
- The [Beijing Stock Exchange 2026 Trading Rules, Articles 3.3.10–3.3.12](https://www.bseinfo.net/jygl_list/200028217.html) specify a CNY 0.01 tick, a 30% limit, and no limit on the first listing day or first delisting-period day. These source rules verify percentages and explicit exception boundaries; they do not provide the app with a per-security daily price-limit feed or a verified listing/delisting status.
- App-side mapping uses security-code prefixes and the displayed security name, not an authoritative exchange classification registry. It computes an explicitly labelled estimate from previous close and shows its assumption in Watch; it does not treat an unavailable limit-up-pool response as zero or use it to populate seal/breadth counts.

## 2026-11-14 functional-source extensions

- The captured Eastmoney minute-flow response in `Resources/Fixtures/eastmoney-fflow-sh600000.json` has observed columns `f51`–`f56` for timestamp, main/small/medium/large/super-large net values. These are vendor-derived values with no verified exchange certification or stable unit contract. The core runtime factory uses a bounded round-robin cache: at most 2 stale watchlist symbols are requested every 10 minutes, only values at most 120 seconds old are returned, and cache hits add zero requests. The two flow rules remain disabled by default, require the `eastmoney_fflow` source tag and provider timestamp, and the tail-session rule only evaluates from 14:30 to 15:00 China time.
- `Resources/Fixtures/eastmoney-scan-firstpage.json` records the observed `clist/get` response used by `EastmoneyMarketScanSource`. Regular runtime scan is bounded to 10 pages/1,000 rows; explicit extended scan uses `pz=100`, derives requested pages from the provider's first-page `total`, caps at 60 pages/6,000 securities, and is process-cached for 15 minutes. Missing/invalid `total` stops after the first page and keeps coverage unknown; duplicate rows, invalid rows, exact-cap truncation and provider-total disagreement keep coverage incomplete. These are provider-relative results, not an independently verified exchange universe. Limit-up, limit-down and broken-seal counts remain nil unless a source actually supplies them; no market rule may turn missing counts into zero.
- `Resources/Fixtures/eastmoney-f10-sh600000.json` records the observable Eastmoney F10/valuation response. An explicit local service caches at most 10 current snapshots per refresh in SQLite schema v4. The `peDynamic` field is deliberately not mapped to `FactorObservation.peTTM`; only semantically matching visible fields are offered to the latest-factor API. Ratios and financial statement data remain absent when not observed; this undocumented endpoint may drift and does not provide point-in-time history for backtests.
- Quote-source adapters use bounded gzip/deflate negotiation and a User-Agent. `QuoteSourceRegistry` applies exponential backoff, circuit opening and one half-open probe after failures, and rejects suspicious non-new-listing quotes whose move exceeds the configured 22% sanity bound. The caller must supply known new-listing codes; if it does not, a valid IPO quote can be rejected as suspect. ETag/Last-Modified conditional request reuse is available to quotes and some clist paths, but is not shared by every news/history endpoint.
- `FunctionalServiceFactory` constructs the Sina → Eastmoney → Tencent quote registry, minute reconciliation, local-limit provider, EventCollector, fundamentals cache, and bounded scan/flow decorators without making requests. `App/MonitorViewModel` now adopts this factory; monitoring, explicit event refresh, local summary/export, cached Analyst and backtest daily-history actions share its store/runtime. Automatic tiered event LLM is assembled only from a valid HTTPS endpoint, model and Keychain-backed key provider loaded at app start; endpoint/model/key changes are picked up after relaunch. Developer tests inject mock event sources and LLM clients only; no App lifecycle or real external requests were run during development.
- `SQLitePortableBackupService` joins the SQLite portable snapshot codec to the existing `BackupCipher`: encrypted files are bounded, decoded and validated before the store's atomic import. Minute/daily bars are included only when the configured row/byte limits are satisfied; otherwise the whole history block is omitted with a reason, and restore leaves destination history unchanged rather than partially replacing it. Raw archive, session ledger and credentials are excluded. Production AES-GCM requires Apple CryptoKit; the key remains caller-supplied and is never stored by the service. App-side passphrase derivation and encrypted file-selection/restore UI remain unimplemented. `LocalEventReportService` assembles reports from local SQLite and supports Markdown/PDF, not PNG; notification delivery is explicit and does not prompt for permission during assembly.
- The default rule catalog includes the original 14 approved families plus estimated-price `seal_break`, `main_flow_surge`, `late_session_pump`, and watchlist-only `dragon_tiger_listing`. Flow thresholds remain configurable and both families default disabled. Dragon-Tiger dates are trade dates, not verified live publication times.


## Daily K-line for explicit local backtests

- The opened [efinance getter implementation](https://raw.githubusercontent.com/Micro-sheep/efinance/main/efinance/common/getter.py) calls `https://push2his.eastmoney.com/api/qt/stock/kline/get` with `fields1=f1,...,f13`, `fields2` taken from `EASTMONEY_KLINE_FIELDS`, `beg`/`end` dates, `klt=101` by default, and `fqt=0/1/2`. Its docstring maps 101 to daily, 0 to unadjusted, 1 to forward-adjusted and 2 to backward-adjusted. This is maintained-client evidence, not an Eastmoney contract.
- The opened [a-share data-source comparison](https://github.com/ychenfen/a-share-data-sources/blob/master/README.md) documents a minimal daily request with `klt=101`, `fqt=2`, the same `f51`–`f61` field range, and warns that an empty `klines` array can follow HTTP 200 and should be treated as a failure. It reports undocumented rate limits and blocking under concurrent requests, and explains that forward-adjusted history can drift as corporate actions are incorporated. These are project observations, not a provider SLA.
- v6's daily-history source is deliberately narrower: one serial request per explicitly supplied watchlist code, shared `push2his.eastmoney.com` budget (4 requests/second and at most 50 per foreground session), `klt=101`, `fqt=0` (unadjusted), local response-shape validation, and an explicit empty-data error. No market-wide list or index constituent list is inferred. Unadjusted corporate-action gaps remain a stated limitation; the app does not claim total-return reconstruction.

`MarketClock` expands the listed ranges to weekdays only. The officially listed weekend dates remain closed through the generic weekend rule. The code treats weekdays in the verified 2022–2026 notice years that are not in the closure map as open, but does not extrapolate into 2027 or later: unsupported weekdays have status `unknown`, and Live Loop does not assume they are trading days. Since full-year SZSE originals could not be opened for 2022, 2023, 2025 or all of 2026, this cross-exchange coverage gap remains explicit; the encoded date values are still directly verified against the official SSE annual notices.

Settings also accepts a bounded local JSON holiday payload whose HTTPS provenance hostname is limited to the SSE/SZSE/BSE official-site allowlist. The import is user-selected and stored locally in `UserDefaults`; there is no automatic calendar network fetch. Imported payloads are not cryptographically signed or independently checked against the linked notice. Only dates explicitly listed as weekday closures become closed; omitted workdays outside the built-in verified years stay `unknown`. A new payload is therefore a user-supplied update, not proof of an official calendar.

## 2026-11-14 local-analysis and routing additions

- `LocalMarketSentiment` aggregates only explicitly supplied optional component values; unavailable components remain missing and are not replaced with guesses. Lab shows only components supported by the currently loaded clist sample and explicitly marks absent limit-up, flow and participation inputs; this is a partial sample score, not whole-market sentiment.
- `LocalBacktestDistribution` now exposes per-date strategy returns and, only with complete date-aligned benchmark bars, per-date arithmetic excess returns plus compounded benchmark and strategy-minus-benchmark totals. Gross traded notional/activity is derived only from actual fill events; turnover, paired holding duration, and realized symbol contribution remain unknown without NAV or closed-trade records. The factor backtest and A-share execution simulator are still separate.
- `EventCollector` persists policy rejection reasons, and SQLite can query reason counts and compare locally stored event keyword frequencies across explicit adjacent 24-hour windows. `LiveEngine` persists complete/partial/empty tick status, missing symbols, and reconcile success/failure; Lab displays the local reason funnel and tick/reconcile strip, distinguishing empty windows from query errors.
- The app's `stockmonitor://` URL scheme is now registered in the generated Info.plist, and the shell already routes validated tab/stock links plus a command palette. Unknown links use a generic error rather than echoing arbitrary URL query text. The app has only Swift syntax parsing here; it still needs Xcode/Apple-device route verification.
